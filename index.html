2026multi-agent

A review fleet for the whole PR queue

I review code for nine engineers. Rather than skim, I built a fleet that reads every open pull request properly and then waits for me

  1. One reviewer agent per open PR, covering correctness, security, tests and UX
  2. Every finding is proved against the actual code before I see it, so authors never get a false alarm
  3. A final pass makes sure no PR was quietly skipped
  4. I get one summary, ranked by which PRs need human eyes, and nothing is posted until I say so

Faster reviews for the team, shorter comments for authors, and my afternoons back for feature work

Claude Code · subagents · GitHub CLI

03

How I approach it

  1. Start from the chore, not the model. I pick something people already do every week and already find tedious, then automate that exact loop
  2. Verify before anyone sees it. Agents check their own work against the source of truth, and a person approves before anything goes out
  3. Know what it costs. Token counts, caching and hard budgets from day one, so a useful tool stays cheap enough to keep running
